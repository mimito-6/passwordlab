Model. Input is encoded as UTF-8, then digested with the selected algorithm. SHA-256 outputs 256 bits (64 hex characters), SHA-384 outputs 384 bits (96 hex characters), SHA-512 outputs 512 bits (128 hex characters). The same input always gives the same hash; changing a single character changes about half the output bits.

How this hash works

Your text is encoded as UTF-8 bytes and passed to the browser's WebCrypto crypto.subtle.digest — the same standard API used by password managers and browsers. There is no server, no analytics, no network request.

FAQ

What is a hash, and what is it used for?

A hash is a fixed-length fingerprint of some input: SHA-256 always produces 64 hex characters, whether the input is one letter or a whole book. It is used to verify integrity — if two files have the same SHA-256 hash, they are the same file for all practical purposes — and to fingerprint data without storing the data itself.

Which algorithm should I pick: SHA-256, SHA-384 or SHA-512?

SHA-256 (256 bits) is the default almost everywhere and is what most download pages publish. SHA-512 (512 bits) gives a larger safety margin and is faster on 64-bit systems; SHA-384 is SHA-512 truncated to 384 bits. For verifying a download, use whichever hash the source published — the algorithm must match, or the comparison is meaningless.

How do I verify a downloaded file?

Copy the hash the download page publishes, pick the same algorithm, drop the file into the file box above, and paste the published hash into the compare box. A match means the file you received is byte-for-byte the file the publisher hashed. A mismatch means it was altered or corrupted in transit — do not run it.

Can a hash be reversed to reveal the original text?

No. Hashing is one-way: there is no key and no decode step. An attacker can only guess inputs and hash them to see if they match — which is why short, predictable inputs (like common passwords) are still guessable even as hashes, and why passwords must be stored with a slow, salted function such as bcrypt or Argon2, not a bare hash.

Why is there no MD5 or SHA-1 option?

Both are broken for collision resistance: researchers can craft two different inputs with the same MD5 or SHA-1 hash, so a matching hash no longer proves the file is genuine. They still appear on old download pages, but for any new verification SHA-256 or stronger is the honest choice.

Does this site see my text or files?

No. Generation and all math happen inside this page. Refreshing destroys the input, so copy the hash before you leave.
