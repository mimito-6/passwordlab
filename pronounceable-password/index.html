How this estimate works

Each syllable is three uniform picks — onset, vowel nucleus, optional coda — drawn with crypto.getRandomValues and rejection sampling (no modulo bias). Nothing is chosen from a word list, so there is no dictionary to attack: the search space is exactly 18,768 syllables, and entropy is syllables × log₂(18,768) = syllables × 14.2 bits.

Quick reference

  • 2 syllables — 28.4 bits. Cracked instantly offline. Only a demo, never a password.
  • 3 syllables — 42.6 bits, about 11 minutes offline. Fine behind a strict lockout, nothing more.
  • 4 syllables — 56.8 bits, about 144 days offline. The default: memorable, and safe where logins are rate-limited.
  • 4 syllables + digit + symbol — 63.7 bits, about 47 years offline. One digit and one symbol buy roughly a decade each in log terms — cheap insurance.
  • 5 syllables — 71.0 bits, about 7,400 years offline. The honest pick for anything that must survive a leaked hash.
  • 6 syllables — 85.2 bits, about 139 million years offline. Stronger than a random 12-character password (78.7 bits) — and far easier to remember.

The trade is real and we will not hide it: pronounceable passwords carry fewer bits per character than random strings, so they need more characters to reach the same strength. What they buy is memory — a password you can recall without writing it down, and will not downgrade to a pet's name after the third reset. If a site lets you paste from a password manager, use the random password generator instead; if a human has to type it, this page is the honest compromise. Either way, store the result in a password manager — memory is a backup, not the vault.

FAQ

What is a pronounceable password?

A password built from random syllables (onset + vowel + optional coda) instead of random characters, so it reads like a made-up word. It is generated by chance, not chosen from a word list, so it has no dictionary meaning to guess.

How strong is a pronounceable password, really?

Each syllable has 18,768 possibilities (46 onsets × 24 vowel sounds × 17 codas), worth 14.2 bits. Four syllables give 56.8 bits — about 144 days against an offline attacker at 10 billion guesses per second. Five syllables give 71.0 bits, about 7,400 years. Six syllables give 85.2 bits, about 139 million years.

Why does capitalizing the first letter add zero bits?

Because the position is fixed. An attacker who knows the rule — "first letter is capitalized" — loses nothing: there is only one way to apply it. Bits come from choices the attacker cannot predict. A digit adds 3.3 bits and a symbol adds 3.6 bits because their values are random, not because they are special characters.

How many syllables should I use?

Four syllables is fine for accounts protected by lockouts and rate limits, where the attacker cannot test guesses freely. Use five syllables (71.0 bits) or more for anything that must survive offline attack — a password vault, an encrypted backup, or a login whose hash could leak. Adding a digit and a symbol to four syllables reaches 63.7 bits, about 47 years offline.

Is it better than a random password?

Per character, no: a random 12-character password from 94 symbols carries 78.7 bits, while four syllables carry 56.8 bits. Per unit of memory, yes: six syllables (85.2 bits) beat that 12-character password and are far easier to recall. The honest trade is bits per character for bits you will actually remember — a password you forget and reset to something weak is worth nothing.
