Model. Have I Been Pwned (HIBP) collects passwords exposed in real data breaches and indexes them by SHA-1 hash. This tool asks the HIBP Pwned Passwords API for the hash range matching your password's 5-character prefix, then checks the remaining 35 characters locally. The count is how many times that exact password appeared in breach corpora — not a count of accounts, and not a strength score.

How k-anonymity protects your password

  1. Hash locally. Your password is hashed with SHA-1 inside your browser. For example, password hashes to 5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8 — you can verify this on the Hash Generator page (SHA-1 is the HIBP protocol's index; see the FAQ on why its broken collision resistance does not matter here).
  2. Send only 5 characters. Only the first 5 hex characters — 5BAA6 — are sent to api.pwnedpasswords.com/range/5BAA6. Five hex characters are 20 bits, so there are 1,048,576 possible prefixes, and the server cannot know which password in that bucket is yours.
  3. Get the whole bucket back. The server returns every hash suffix sharing that prefix — typically around two thousand entries (measured 1,977 for prefix 5BAA6 and 2,509 for 00000 on 25 November 2026). Responses are padded to a uniform size (Add-Padding: true), so even the response length leaks nothing.
  4. Match locally. Your browser checks whether the remaining 35 characters (1E4C9B93F3F0682250B6CF8331B7EE68FD8 for password) appear in that list. The full hash is never transmitted, and the server never learns the result.

These are not estimates: they are the counts the HIBP API returned on the date above, and they grow as new breaches are added. Any password on this kind of list is not a password at all — it is a public string attackers try before they even start guessing.

A "not found" result is good news with a limit: it only means the password is absent from the breaches HIBP knows about. It says nothing about guessability — a short random-looking password such as xK9!q may be absent from every breach and still fall to a fast offline attack in seconds. Pair this check with the Strength Checker: breach absence and cracking resistance are two different properties, and a password needs both.

FAQ

Does this site send my password anywhere?

No. Your password is hashed with SHA-1 inside your browser, and only the first 5 characters of that hash are sent to the Have I Been Pwned database. The server returns every hash sharing those 5 characters (typically around 2,000 entries), and the match against the remaining 35 characters happens on your device. The server cannot tell which of those ~2,000 candidates was yours.

What does "seen N times" mean?

It is the number of times that exact password appeared in the breach data Have I Been Pwned has collected. It counts occurrences across breach corpora, not individual accounts — the same password in five breaches counts five times, and one person reusing it in five places still counts as the same password.

My password was not found — is it safe?

Not necessarily. "Not found" only means the password is absent from the breach corpus Have I Been Pwned knows about. A short or predictable password can be absent from every breach and still be guessed in seconds. Run it through the Strength Checker as well — absence from breaches and resistance to guessing are two different properties.

Why SHA-1? Isn't SHA-1 broken?

SHA-1 is used here only because the Have I Been Pwned protocol defines it as the lookup key — it is a bucket index, not password storage. Its broken collision resistance does not matter for this job: nobody is trusting the hash to prove anything, and the hash is never stored or used to verify your password. Password storage is a different problem and needs a slow, salted function such as bcrypt or Argon2.

What should I do if my password was found in a breach?

Change it immediately, everywhere you use it — not just on the site that was breached. Attackers try leaked passwords on other sites (credential stuffing), so a reused password is compromised everywhere at once. Generate a fresh one with the Password Generator or a passphrase with the Passphrase Generator, store it in a password manager, and turn on two-factor authentication where it is offered.

What if the check fails or I am offline?

Then no result is shown at all. A failed check is never presented as a clean bill of health — the page says plainly that the breach database could not be reached and asks you to try again later. The hashing still happens locally, but without the database there is nothing honest to report.
